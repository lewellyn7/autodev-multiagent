## 三、待落地优化（优先级排序）

### P0 — 吞吐量瓶颈（改动小，收益大）

#### 1. `encode_texts()` 连接池化
**现状**：每次调用 `httpx.post()` 创建新连接，无连接池
**问题**：批量 encoding 时每个文本单独建连，vLLM QPS 受限
**改法**：`httpx.Client` 单例 + `max_connections=20`

```python
# 当前（每次 new connection）
def encode_texts(texts):
    response = httpx.post(url, json={...}, timeout=30.0)  # 无连接复用

# 改为（连接池复用）
_http_client: Optional[httpx.Client] = None

def _get_http_client() -> httpx.Client:
    global _http_client
    if _http_client is None:
        _http_client = httpx.Client(
            timeout=30.0,
            limits=httpx.Limits(max_connections=20, max_keepalive_connections=10),
        )
    return _http_client

def encode_texts(texts):
    client = _get_http_client()
    response = client.post(url, json={'input': texts, 'model': model_name})
```

**收益**：批量 encoding 延迟 −60%，vLLM QPS 利用率 ↑

#### 2. 查重 API O(n²) → O(n)
**现状**：`find_duplicates()` 双重循环 1000×1000，内存全量加载

```python
# 当前 O(n²)
for i in range(len(projects)):
    for j in range(i+1, len(projects)):
        score = compute_similarity(pi, pj)
```

**改法**：
- SQLite/PG 索引：`CREATE INDEX idx_favorites_title ON favorites(title);`
- 分块处理：100 条/批，避免内存峰值
- 预过滤：标题完全不同的直接跳过（TF-IDF 命中再比）

```python
# 改后 O(n)，预过滤
# 先按标题分桶，桶内再两两比对
from collections import defaultdict
buckets = defaultdict(list)
for p in projects:
    bucket_key = p['title'][:4]  # 前4字同则可能重复
    buckets[bucket_key].append(p)
# 只在桶内比对，大幅减少比较次数
```

**收益**：查重延迟 10s → <1s

### P1 — 并发架构升级

#### 4. 采集任务批量提交
**现状**：每个 URL 单独调用 `crawler.crawl()`，串行解析
**改法**：asyncio.gather 批量并发（受限于 `MAX_CONCURRENT` 信号量）

```python
async def run_collection():
    # 从 DB 拿 N 条待采集
    urls = await fetch_pending_urls(limit=MAX_CONCURRENT * 2)
    sem = asyncio.Semaphore(MAX_CONCURRENT)

    async def crawl_one(url):
        async with sem:
            return await _run_crawl_task(url)

    tasks = [crawl_one(u) for u in urls]
    results = await asyncio.gather(*tasks, return_exceptions=True)
```

**收益**：采集吞吐量 ×3~5

#### 5. DB 批量写入替代逐条 INSERT
**现状**：`save_harvest_records` 逐条插入 100 条记录 = 100 次 round-trip
**改法**：PostgreSQL `execute_batch` / `copy_from`

```python
# 当前：100 次 INSERT
for record in records:
    await conn.execute("INSERT INTO favorites ...", record)

# 改后：1 次批量 INSERT
await conn.executemany(
    "INSERT INTO favorites VALUES ($1, $2, ...)",
    records  # list of tuples
)
```

**收益**：入库延迟 −80%

### P2 — 资源化&监控

#### 7. 添加关键 Metrics 暴露
**现状**：有 `health_monitor.py` 采集 latency/throughput，无可观测出口
**改法**：新增 `/metrics` 端点（Prometheus 格式），对接现有 PG exporter

```python
# app/api/routes/metrics.py
@router.get("/metrics")
def prometheus_metrics():
    from app.services.health_monitor import HealthMonitor
    hm = HealthMonitor()
    latency = hm._calc_avg_latency()
    throughput = hm._calc_throughput()
    return Response(
        f"# HELP crawl_latency_ms Average crawl latency\n"
        f"crawl_latency_ms {latency}\n"
        f"# HELP crawl_throughput Current throughput\n"
        f"crawl_throughput {throughput}\n",
        media_type="text/plain"
    )
```
