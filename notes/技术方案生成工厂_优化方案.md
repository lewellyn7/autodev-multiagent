# 技术方案生成工厂 — 鲁棒性优化方案

## 一、现状分析

### 主工作流 (技术方案生成工厂) — 23 节点

```
用户输入 → 条件分支(首次/重续)
  ├─ 首次 → 意图识别
  │         ├─ true:  生成正文 → 大纲生成-子工作流 → 答复
  │         └─ false: 大纲生成-子工作流 → 数据存入 → 答复章节情况
  └─ 重续 → 执行态路由器 → 任务判断
              ├─ 任务阶段:
              │   知识检索 → 知识库清洗 → LLM章节撰写 → 存储全文 → 章节任务
              └─ 收尾阶段:
                  分段润色LLM → 追加正文 → 存入草稿
```

### 脆弱点（网络波动直接中断）

| 节点 | 风险 | 当前处理 |
|------|------|---------|
| **知识检索** (RAG) | 超时/网络波动 → 直接抛异常 | 无 |
| **LLM章节撰写** | API 限流/网络抖动 → 整流程终止 | 无 |
| **Markdown转Docx** | 文件服务抖动 → 生成失败 | 无 |

## 二、变更方案

### 方案 A（推荐）：新建鲁棒性子工作流，替换主流程节点链

#### 子工作流：章节迭代-鲁棒版

```
输入变量:
  - project_name (string)
  - project_info (string)
  - section_title (string)
  - section_points (string)
  - session_id (string)
  - technical_stack (string)
  - current_index (number)
  - full_text_so_far (string, optional)

节点:
  1. Start (用户输入)
     └─ 输出: project_name, project_info, section_title, section_points,
             session_id, technical_stack, current_index, full_text_so_far

  2. LLM (章节生成-鲁棒) ← 核心 LLM 调用
     ├─ 输入: project_name, project_info, section_title, section_points,
             technical_stack, current_index, full_text_so_far
     ├─ 重试: 开启 (最多 2 次，间隔 5s)
     └─ Prompt:
        你是一名资深技术方案撰写工程师。根据以下信息撰写技术方案章节。

        项目名称: {{project_name}}
        项目简介: {{project_info}}
        当前章节: {{section_title}}
        章节要点: {{section_points}}
        技术约束: {{technical_stack}}
        已有内容: {{full_text_so_far}}

        要求:
        1. 按{{section_points}}展开，每个要点≥3段
        2. 结合项目实际需求，不套用通用模板
        3. 出现网络/知识库不可用时，基于通用标准撰写，不得中断
        4. 输出格式: markdown

  3. Code (追加正文-鲁棒)
     ├─ 输入: full_text_so_far (string), llm_output (string), section_title (string)
     └─ 代码:
        def main(full_text_so_far, llm_output, section_title):
            separator = f"\n\n## {section_title}\n\n"
            new_text = (full_text_so_far or "") + separator + llm_output
            return {"appended_text": new_text}

  4. End (输出)
     └─ 输出: appended_text (from Code node)
```

#### 主工作流变更点

**替换目标**：原 `知识检索 → 知识库清洗 → LLM章节撰写 → 存储全文 → 章节任务` 这 5 个节点

**替换为**：
```
[子工作流调用: 章节迭代-鲁棒版]
  ├─ 输入映射:
  │   project_name = $SYS.var.project_name
  │   section_title = $变量.当前章节标题
  │   section_points = $变量.当前章节要点
  │   technical_stack = $SYS.var.technical_stack
  │   current_index = $conversation.current_index
  │   full_text_so_far = $变量.全文内容
  └─ 输出: appended_text → 更新 $变量.全文内容
```

### 方案 B（平替）：在现有节点内增强，不新增子工作流

如果暂时无法改主流程结构，在以下节点做增强：

#### 1. 知识检索（节点替换为子工作流调用）

将 `知识检索` 节点替换为 `章节rag-子工作流` 调用（你已有此子工作流，今天刚加了重试逻辑）。

**操作**：Dify UI → 选择 `知识检索` 节点 → 右上角 `转为子工作流` → 选择 `章节rag-子工作流`

#### 2. 知识库清洗（增加 fallback）

```python
def main(rag_results: list):
    res = {
        "formatted_text": "（知识库检索失败，已基于通用技术标准撰写。实际项目中请补充相关技术文档至知识库。）"
    }
    if not rag_results or not isinstance(rag_results, list):
        return res
    context_list = []
    for i, item in enumerate(rag_results):
        title = str(item.get("title", f"参考素材 {i+1}")).strip()
        content = str(item.get("content", "")).strip()
        if content:
            context_list.append(f"### 技术素材 {i+1}：{title}\n{content}")
    if context_list:
        res["formatted_text"] = "\n\n".join(context_list)
    return res
```

#### 3. LLM章节撰写（开启内置重试）

在 Dify UI → LLM 节点设置中：
- **高级设置** → **失败重试**：开启
- **最大重试次数**：2
- **重试间隔**：5 秒

## 三、预期效果

| 场景 | 优化前 | 优化后 |
|------|--------|--------|
| RAG 网络抖动 | 整流程中断 | 自动重试 2x，仍失败则用通用内容继续 |
| LLM API 限流 | 流程中断 | 自动重试 2x，间隔 5s |
| 知识库为空 | 返回空，下游报错 | 返回友好提示，继续生成 |
| Docx 服务抖动 | 流程中断 | 返回错误信息，可手动重试 |
